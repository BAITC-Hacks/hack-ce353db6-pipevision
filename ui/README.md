# WindAgent — панель оператора ВЭС

Панель открывается на прогнозе ВЭС «Нурлы». По умолчанию показана **ретроспектива 10.02.2026, 23:00 UTC+5**, а не текущая телеметрия. Мощность рассчитывает то же ядро, что и CLI `wind-agent`.

## Запуск

```bash
make setup-ui
make ui                       # http://localhost:8501
# другой порт: make ui UI_PORT=8601
```

Без make:

```bash
uv pip install --python .venv/bin/python -e ".[ui]" -c requirements.lock
.venv/bin/streamlit run ui/app.py --server.port 8611 --server.headless true
```

UI-зависимости находятся в extra `ui`. Railway использует `deploy/Dockerfile.ui`.
Прогноз по умолчанию доступен из дискового кэша без сети. Для оперативного прогноза и исследования новых площадок нужны погодные API. AI-пояснения требуют `OPENAI_API_KEY`; без ключа остаются прогноз, проверки и ответы по правилам.

## Основной экран

1. Рабочее пространство: «Оператор» или «Исследование площадки».
2. Дата и время выпуска, целевой период, короткая сводка и наиболее существенное предупреждение. Остальные предупреждения доступны в раскрываемом блоке.
3. Три показателя: выработка, пик мощности, средняя ширина почасовой полосы.
4. Один график мощности: текущий прогноз, предыдущий выпуск и факт, когда он есть. Ветер доступен в подсказке графика и объяснениях; второй оси нет.
5. Экспорт выбранного периода в CSV и отчёт полного выпуска 48 ч.
6. Компактная схема «Погода → Данные → Прогноз → Проверка».
7. Раскрываемые блоки: «Спросить агента», «Почему такой прогноз и что изменилось», «Данные и проверка качества».

В последнем блоке выбирается один раздел: почасовые данные, тестовый период, факт и точность, журнал расчёта или 3D. Тяжёлая 3D-сцена создаётся только при выборе этого раздела. Полный технический отчёт, трасса инструментов и журналы сохранены, но не занимают основной экран.

В боковой панели — режим, дата и час выпуска, горизонт 24/48 ч, AI-пояснения и «Рассчитать». Изменение даты/режима отмечает старый результат; ошибка нового расчёта явно оставляет предыдущий. Выбор горизонта пересчитывает отображаемые сводку, предупреждения, объяснения и контекст ответов по одному периоду. Технический журнал и скачиваемый отчёт относятся к полным 48 ч и подписаны отдельно.

## Схема и анимация

- Во время расчёта стадии обновляются по реальным событиям ядра. Ожидание обозначено пульсом рядом со статусом. Следующий шаг не объявляется выполненным по таймеру.
- После явного запуска пользователя — один короткий проход света по схеме (1,05 с). Начальная загрузка, смена горизонта и раскрытие деталей статичны.
- Включение AI-пояснений сопровождается локальным акцентом на 0,9 с. Этот режим меняет объяснения и диалог, а не численную модель мощности.
- `prefers-reduced-motion` отключает движение. Текст результата доступен сразу; эффект его не задерживает.
- Постоянного видео, canvas, печатной машинки и имитации «хода мыслей» нет. Существующий `agent_intro.mp4` сохранён как исходный ассет, но панель его не загружает.

## Исследование площадки

Отдельное пространство содержит карту Казахстана, форму координат и состава ВЭС, 3D, оценку ресурса ERA5 за год, прогноз 48 ч переносом модели и отчёт. Клик по ячейке атласа заполняет координаты. Ошибка отдельного шага сохраняется в результатах и не отменяет остальные шаги. Успешные исследования кэшируются в сессии.

Это предварительная оценка: для новой площадки нет местной SCADA и валидации. ERA5 имеет крупную сетку, кривая мощности обобщённая. API может ограничивать частоту запросов; ожидание и ошибки видны в статусе.

## Смысл показателей

- «Расчёт готов» означает завершённые автоматические проверки, а не разрешение на диспетчерское планирование.
- Ширина полосы характеризует разброс прогноза; узкая полоса не доказывает высокую точность.
- Почасовые P10/P90 турбин откалиброваны моделью. Границы парка складываются из границ турбин; покрытие агрегированного ряда отдельно не доказано. Суммы почасовых границ в таблице **не являются откалиброванным 80%-м интервалом энергии**.
- Геометрия наветренных турбин из OSM — приближение, а не измерение потерь в следе.
- Качество оценивается по факту SCADA. Отсутствие факта не подменяется прогнозом. Ограничения и проверка вариантов модели описаны в [исследовании прогноза](../docs/research/forecast_improvement.md).
- В разделе «Факт и точность» опубликован исторический бэктест с периодом, ошибкой, смещением и покрытием по турбинам и лагам. Перед показом проверяются хэши модели, исходников и метрик по `models/validation_manifest.json`. Несогласованные или отсутствующие файлы скрывают метрики. Финальный артефакт переобучен на всей истории; этот бэктест проверяет конфигурацию отдельной моделью и не измеряет точность текущего выпуска.

## Файлы и проверки

| Файл | Назначение |
|---|---|
| `ui/app.py` | Компоновка, параметры, графики, раскрытие деталей |
| `ui/core.py` | Мост к ядру, анализ горизонта, сводка и проверяемые ответы |
| `ui/motion.py` | Индикатор фактического прогресса и акцент переключателя |
| `ui/assets/agent_card.html` | Компактная схема с конечной анимацией |
| `tests/test_ui_smoke.py` | Запуск обоих пространств и базовые сценарии |
| `tests/test_operator_semantics.py` | Горизонты, единицы, предупреждения, ответы |
| `tests/test_ui_motion.py` | Состояния схемы и доступность анимации |

```bash
python -m pytest tests/test_ui_smoke.py tests/test_operator_semantics.py tests/test_ui_motion.py -q
```

Результаты UI пишутся в `outputs/tmp/ui`, не в протокольные каталоги. При замене файла модели следующий расчёт обновляет кэш; старый результат сохраняет хэш использованного артефакта. После обновления исходников ядра сервер нужно перезапустить. Проверено на закреплённом Streamlit 1.64. Панель пока не содержит авторизации и рабочего процесса согласования прогноза.
