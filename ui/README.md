# WindAgent — панель оператора ВЭС (Streamlit)

Рабочее место специалиста по ветроэнергетике. Панель открывается на действующей ВЭС «Нурлы» и сама строит последний протокольный выпуск прогноза (10.02.2026, 23:00, без LLM). Рядом с 3D-сценой площадки — тепловая карта ветрового ресурса Казахстана. Специалист выбирает на ней перспективный участок, уточняет координаты и состав ВЭС и запускает исследование площадки. На выходе получаются годовая оценка ресурса и выработки по ERA5, прогноз на 48 ч по модели «Нурлы» (переносом) и отчёт для защиты проекта перед руководством. Прогноз считает то же ядро, что и CLI `wind-agent`; панель передаёт параметры и показывает результат.

## Запуск

```bash
make setup-ui   # один раз: extra [ui] — streamlit (altair идёт вместе с ним) и plotly (карта Казахстана)
make ui         # http://localhost:8501; другой порт: make ui UI_PORT=8601
```

Без `make`:

```bash
uv pip install --python .venv/bin/python -e ".[ui]" -c requirements.lock
.venv/bin/streamlit run ui/app.py --server.port 8611 --server.headless true
```

Зависимости панели вынесены в extra `ui` (`streamlit`, `plotly`; версии закреплены в `requirements.lock`), поэтому `make setup`, тесты ядра и CLI их не ставят. Сервер (Railway, Docker) собирается из `deploy/Dockerfile.ui` (`pip install -e ".[ui]" -c requirements.lock`) и запускает ту же команду `streamlit run ui/app.py`. LLM включается, только если в `.env` или окружении есть `OPENAI_API_KEY`.

Без сети открывается вся главная страница «Нурлы»: прогноз берётся из кэша `data/cache/openmeteo`, атлас — из `data/atlas/kz_wind_atlas.csv`, сцена — из `viz/data/viz_data.js`. Подложка карты своя, без внешних тайлов. Исследованию площадки нужна сеть: Open-Meteo (ERA5, прогноз, рельеф) и NASA POWER.

## Экран (сверху вниз)

1. **Шапка.** «WindAgent · <площадка>», паспорт площадки и статус ядра: версия модели и какие модули площадочного анализа есть в сборке (`atlas`, `assess`, `vizdata`).
2. **Переключатель рабочих пространств** (`st.segmented_control`, состояние в `st.session_state["workspace"]`): «Оператор» и «Исследование площадки».
3. **Карточка агента** — над обоими пространствами, на всю ширину (подробнее — раздел ниже). В «Операторе» рассказывает о выпуске «Нурлы», в «Исследовании» — о кандидате или исследованной площадке. Под карточкой диалог с агентом.
4. **«Оператор»** — всё по выпуску «Нурлы»:
   - строка состояния выпуска: режим, горизонт, паспорт, источник погоды, модель, решение агента (при 24 ч с пометкой «по выпуску 48 ч»);
   - «Риски и предупреждения · N ч» — лента по уровням: интервал, значение и порог, действие;
   - пять KPI со спарклайнами, веерный график парка P10–P90, «Почему такой прогноз»;
   - «Изменения к выпуску D−1» на общих часах: энергия, MAE, смещение, наибольшее изменение и его час;
   - действия: «Экспорт CSV» (`FORECAST_COLUMNS`) и «Отчёт .md»;
   - 3D-сцена «Нурлы» — свёрнута в expander (сцена запускается, только когда iframe стал видимым);
   - вкладки «Таблицы и выгрузка», «Тестовый период» (сшитый прогноз 31.01–27.02.2026, ревизии, «Открыть выпуск»), «Факт и точность» (MAE, RMSE, смещение, покрытие P10–P90), «Журнал агента» (решение, сверка чисел, полная трасса, отчёт, журнал ядра).
5. **«Исследование площадки»**:
   - ряд 60/40: слева 3D-сцена (до исследования — «Нурлы», после — сцена новой точки: `vizdata.viz_payload` + `vizdata.viz_html`, рельеф DEM и раскладка N турбин); справа карта Казахстана — `plotly go.Choroplethmap` (MapLibre, без токена) по `atlas.grid_cells_geojson()`, цвет — ветер на 100 м (`ws100_est`, Turbo), контур страны, города, маркеры «Нурлы» (белый), кандидата (янтарный) и исследованной площадки (зелёный). Клик по ячейке переносит координаты её центра в форму (почти прозрачный слой `Scattermap` с центрами ячеек отдаёт lat/lon в `selection.points`);
   - под картой строка ближайшей ячейки атласа и форма: широта, долгота (шаг 0,01°), число турбин, МВт, название; «Исследовать площадку» (неактивна вне Казахстана) и «Вернуться к «Нурлы»» (возвращает в «Оператор»);
   - ход исследования по шагам в `st.status`: атлас → ERA5 за год и оценка ресурса → прогноз 48 ч → рельеф и 3D-сцена → отчёт. Шаги независимы: ошибка одного не останавливает остальные;
   - результаты: средний ветер 100 м, Вейбулл k / c, КИУМ, годовая выработка N × МВт, отношение ветра к «Нурлы»; месячный ход, роза ветров, суточный ход; прогноз 48 ч переносом модели; «Отчёт для руководства» (`assess.management_report`) со «Скачать .md» и пометкой LLM/сверки. Результаты кэшируются в `st.session_state` по ключу (широта, долгота, N, МВт).

**Боковая панель** — только параметры выпуска «Нурлы»: режим («Ретроспектива» или «Оперативный»), дата выпуска с кнопками D−1 / D+1, час выпуска, горизонт 24 или 48 ч, LLM, «Рассчитать». Своя площадка задаётся картой и формой, её прогноз всегда оперативный.

**Горизонт 24 ч.** Все блоки «Оператора» считаются по одному периоду `lead_hours ≤ 24`: KPI, предупреждения (рампы, штили и окна ТО только внутри периода), «Почему такой прогноз» (доли часов, разброс ансамбля, сравнение с нормой месяца), изменения к D−1 и ответы агента в диалоге. Для этого `core.horizon_analysis(res, h)` повторяет `tools.analyze_forecast` на усечённом прогнозе (кэш в `ForecastResult.horizon_cache`). Решение и текст агента в карточке относятся к выпуску целиком (48 ч) и так подписаны.

Графики строятся по ряду парка. По турбинам данные есть только в таблицах.

## Карточка агента и диалог

Агент — главный элемент панели: карточка сразу под шапкой, выше всего остального.

- **Визуал (≈35 % ширины).** Canvas-анимация «ядро агента»: поток частиц ветра стягивается к ротору-ядру, вокруг — орбита инструментов цикла (`fetch_weather → prepare_data → run_model → analyze_forecast → verify_narrative → write_report`; для площадки — атлас → ERA5 → прогноз → рельеф → отчёт). Активный инструмент подсвечивается лучом от ядра, выполненные — цветом статуса. `requestAnimationFrame`, анимация останавливается, когда вкладка скрыта; `prefers-reduced-motion` — статичный кадр. Если в `ui/assets/` лежит `agent_intro.webm` или `agent_intro.mp4` (≤ 8 МБ), он встраивается как data-URI и играет фоном под canvas (`autoplay muted loop playsinline`); файла нет — только canvas.
- **Ход мыслей (справа).** Лента шагов из `res.trace` появляется по одному: спиннер → галочка, время шага в мс, итог шага; шаги LLM помечены. Затем крупно решение (`ACCEPT` / `FLAG` / `RECALCULATE`), «проверено чисел N · не подтверждено M» из `fact_check` и сообщение агента с эффектом печатной машинки (текст LLM или шаблон; метка «LLM gpt-5-mini» или «правила»). Клик по сообщению — показать текст сразу.
- **Исследование площадки.** Та же лента — пять шагов исследования со временем (`run_assessment` пишет `timings`), итог — рекомендация по площадке, в сообщении — раздел «Резюме» отчёта для руководства (`core.report_summary`), статус LLM/шаблон и сверки. До исследования — кандидат по атласу и план шагов.
- **Эффект запуска.** Первый показ карточки в сессии — разворачивание от центра со вспышкой и сканирующей линией (~1,1 с, CSS keyframes), потом лента шагов. Блокирующих заставок нет.
- **Без повторной анимации.** HTML карточки строит `core.agent_card_html(payload, animate, intro, nonce)` из шаблона `ui/assets/agent_card.html`. Ключ — хэш данных карточки + идентификатор сессии; для того же ключа панель отдаёт ту же строку HTML (`st.session_state["_card_cache"]`), поэтому перезапуски Streamlit (смена горизонта, вопрос в чат) не перезагружают iframe. Если iframe всё же пересоздан, `sessionStorage` внутри него помнит ключ — лента и текст показываются сразу, без печати.
- **Диалог.** Под карточкой `st.chat_input` «Вопрос агенту о прогнозе или площадке»; история — `st.session_state["agent_chat"]` по контексту (выпуск и горизонт или площадка), показываются последние 6 реплик (`st.chat_message`). Ответ — `core.ask_agent(question, res, study, history, horizon)` → `{answer, llm_used, fact_check, model}`:
  - с ключом OpenAI — LLM (`llm.llm_settings`, `llm.make_client`, `llm._request_kwargs`) по компактному JSON: анализ выпуска по горизонту панели, показатели панели (МВт, час пика, окна штиля, рампы), при открытой площадке — оценка ресурса; системный промпт: только числа из JSON, на русском, кратко, без имён полей. Затем `tools.verify_narrative(answer, allowed)`, где `allowed` — показатели анализа + панели + `assess.allowed_facts(assessment)`. Неподтверждённые числа — один повтор с их перечнем (как в `assess.management_report`), потом честная пометка «Не подтверждено данными: …» под ответом;
  - без ключа — детерминированный ответ по ключевым словам: энергия за горизонт (МВт·ч, ч.н., P10–P90, по суткам), пик, рампы, штили и окна ТО, лучший и худший день, уверенность, решение агента, норма месяца; для площадки — КИУМ, годовая выработка, сравнение с «Нурлы». Иначе — «для свободного вопроса нужен ключ OpenAI». Ответ по правилам тоже проходит сверку чисел.

## Как устроено

| Файл | Назначение |
|---|---|
| `ui/app.py` | страница Streamlit: шапка, переключатель «Оператор» / «Исследование площадки», карточка агента и диалог, KPI, веерный график, риски, изменения к D−1, сцена и карта, раздел исследования, вкладки |
| `ui/core.py` | мост к ядру без зависимости от Streamlit: `run_forecast(params) → ForecastResult`; `run_assessment(StudyParams, wx, progress) → dict`; `horizon_analysis`; карточка агента (`forecast_card`, `study_card`, `idle_study_card`, `agent_card_html`) и `ask_agent`; атлас для карты, агрегаты, окна рамп и штиля, лента предупреждений, факт и точность |
| `ui/assets/agent_card.html` | шаблон карточки агента: canvas-визуал, лента шагов, решение, печать сообщения (данные подставляет `core.agent_card_html`) |
| `ui/assets/agent_intro.mp4` / `.webm` | необязательное видео-фон визуала карточки (≤ 8 МБ) |
| `.streamlit/config.toml` | тема: нейтральный акцент (красный только для ошибок, янтарный для предупреждений) |
| `tests/test_ui_smoke.py` | мост без сети (контур, центры ячеек, шаги исследования без модулей и с ошибкой), ответ агента по правилам без ключа, HTML карточки агента, запуск страницы и обоих пространств через `streamlit.testing.AppTest` |

- **Модули площадочного анализа** (`wind_agent.atlas`, `wind_agent.assess`, `wind_agent.vizdata`) импортируются по требованию (`core._optional`). Если модуля нет, раздел показывает нейтральный статус «недоступно в этой сборке», и панель не падает. Без атласа карта рисует контур и сетку центров 0,5° без цвета, клик по-прежнему выбирает точку.
- **`run_assessment`**: `atlas.nearest_cell` → `assess.assess_site(site, wx, start="2025-01-01", end="2025-12-31", progress)` → `run_forecast(ForecastParams(site="custom", mode="live"))` → `vizdata.viz_payload(site, forecast, fetch=True, progress)` + `vizdata.viz_html(payload, issue)` → `assess.management_report(a, forecast_summary, use_llm=есть ключ)`. `progress(i, шаг, состояние)` обновляет `st.status`, сообщения модулей ядра показываются в строке текущего шага. Возвращает `{assessment, forecast_result, viz_html, report, cell, errors, skipped, elapsed_s}`.
- **Вызов ядра для прогноза.** `run_forecast` вызывает `orchestrator.run_cycle`. Параметры `site`, `issue_hour` и `out_dir` передаются, только если `run_cycle` их принимает (`inspect.signature`). Пороги рамп, штиля и уверенности берутся из `wind_agent.agent.tools`.
- **Запись файлов.** Панель не пишет в `outputs/forecasts`, `outputs/reports` и `outputs/live`: файлы прогона попадают в `outputs/tmp/ui/<replay|live>/<площадка>/`.
- **Кэш.** `WeatherClient` (дисковый кэш Open-Meteo), модель и факт SCADA — `st.cache_resource`; HTML сцены «Нурлы» и ячейки атласа — `st.cache_data`.

## Ограничения

- **Своя площадка.** Прогноз 48 ч — перенос модели «Нурлы»: одна виртуальная турбина в ячейке сетки погоды, обобщённая кривая мощности, ошибка выше. Годовая оценка — ERA5 (~31 км) без учёта следа и потерь в сети. Для решения об инвестициях нужны мачтовые измерения или лидар.
- **Лимиты Open-Meteo** (~600 запросов в минуту, каждая точка DEM — запрос). При 429 модули ядра ждут и повторяют запрос, исследование в это время может идти минуту и больше. Если лимит не восстановился, шаг помечается ошибкой, остальные шаги выполняются.
- **Клик по карте** обрабатывает MapLibre (`click` в режиме панорамирования). Повторный клик по той же ячейке событие не отправляет, координаты такой ячейки меняются в форме.
- **Версии Streamlit.** Проверено на Streamlit 1.64 и plotly 7.1. Аргументы, которых нет в старых версиях, отбрасываются (`_kw`). `st.components.v1.html` в 1.64 выдаёт предупреждение об устаревании, при его удалении используется `st.iframe`.
- **Обновление ядра.** Модули ядра импортируются при старте сервера. После обновления кода ядра или модели перезапустите `make ui`.
- **Карточка агента.** Решение и текст агента — по выпуску целиком (48 ч), даже при горизонте 24 ч. Видео-фон больше 8 МБ не встраивается. Эффект печати и ленты не повторяется в той же вкладке браузера (`sessionStorage`); после перезагрузки страницы (новая сессия Streamlit) проигрывается снова.
- **Диалог.** LLM отвечает по снимку данных панели, без вызова инструментов и пересчёта прогноза; ответ занимает 5–15 с. История хранится в сессии браузера.
- **Пользователи.** Панель рассчитана на одного специалиста: нет авторизации, исследования хранятся в сессии браузера.
