# WindAgent — панель оператора ВЭС (Streamlit)

Веб-панель поверх ядра `wind_agent`. Оператор задаёт площадку, режим, дату и час выпуска, горизонт, включает или выключает LLM и нажимает «Рассчитать». На экране появляются почасовой прогноз выработки, предупреждения, отчёт агента и трасса его шагов. Прогноз считает то же ядро, что и CLI `wind-agent`; панель только передаёт параметры и показывает результат.

## Запуск

```bash
make setup-ui   # один раз: streamlit (extra [ui] в pyproject.toml; altair ставится вместе с ним)
make ui         # http://localhost:8501; другой порт: make ui UI_PORT=8601
```

Без `make`:

```bash
uv pip install --python .venv/bin/python -e ".[ui]" -c requirements.lock   # или: .venv/bin/pip install "streamlit>=1.38"
.venv/bin/streamlit run ui/app.py
```

Streamlit вынесен в дополнительную группу `ui`, поэтому `make setup`, тесты и CLI его не устанавливают. LLM включается, только если в `.env` или окружении есть `OPENAI_API_KEY`. Без ключа переключатель неактивен, и агент работает по детерминированным правилам. Сервер (Railway, Docker) собирается из `deploy/Dockerfile.ui` и запускает ту же команду `streamlit run ui/app.py`.

## Экран

**Боковая панель.** Только элементы управления, пояснения спрятаны в значки `?`:

- «Площадка» — ВЭС «Нурлы» или своя площадка (широта, долгота, число турбин, номинал в МВт, название);
- «Режим» — «Ретроспектива» или «Оперативный»;
- «Дата выпуска» (01.03.2024–27.02.2026) и «Час выпуска» — только для ретроспективы;
- «Горизонт» — 24 или 48 ч;
- переключатель «LLM»;
- кнопка «Рассчитать».

При первом открытии панель сразу считает прогноз по параметрам по умолчанию: «Нурлы», 10.02.2026, 23:00, без LLM. Данные берутся из кэша, расчёт занимает меньше секунды.

**Шапка.**

- Заголовок «WindAgent · <площадка>».
- Строка состояния: режим (РЕТРО или LIVE) и время выпуска с пометкой UTC+5, горизонт, мощность площадки, источник погоды, версия модели. Последним идёт бейдж решения агента: янтарный для `flag`, красный для `recalculate`.
- Под ней служебная строка: время расчёта, число запросов к Open-Meteo, статус анализа, выпуск для сравнения.
- Для своей площадки — однострочный баннер о переносе модели.

**Пять KPI** (ряд парка, `st.metric` со спарклайнами):

| Карточка | Что показывает |
|---|---|
| Энергия 48 ч | МВт·ч; в подписи — P10–P90 и часы номинала |
| D+1 / D+2 | энергия по суткам; `delta` к выпуску D−1 только по общим часам, `delta_color="off"` |
| Пик P50 | МВт и час пика |
| Риск рампы | максимальный \|ΔP50\| за час против порога агента |
| Уверенность | «высокая», «средняя» или «низкая» по средней ширине P90−P10 против порога агента |

Превышение порога выделяется янтарной подписью.

**Веерный график.** Переключатели «Ряд» (парк или турбина; ряды берутся из данных) и «Единицы» (МВт или доля номинала).

- Полоса P10–P90 — приглушённая серо-синяя.
- P50 текущего выпуска — тонкая линия, тёмная в светлой теме и светлая в тёмной.
- P50 выпуска D−1 — серый пунктир на общих часах.
- Факт SCADA — точки. Есть для ретроспективных дат «Нурлы» до 31.01.2026.
- Ветер на 100 м — на правой оси.
- Линия «выпуск», границы суток с подписями «D+1 · дд.мм».
- Фоном — окна рамп (янтарь) и штиля (серый).

**Вкладки**

- «Предупреждения (N)». Одна строка на предупреждение: уровень словом и цветом, заголовок («Резкая рампа», «Существенная ревизия», «Окно штиля для ТО», …), интервал по местному времени, значение и порог, действие. Сначала критичные, потом предупреждения, потом сведения; внутри уровня — по времени. После расчёта предупреждения уровня warning дублируются всплывающим `st.toast`.
- «Таблицы и выгрузка». Выработка по суткам для турбин и парка в формате «P50 [P10–P90]», почасовая таблица (сворачивается), кнопки «Экспорт CSV» (контракт `FORECAST_COLUMNS`, как `outputs/forecasts/*.csv`) и «Экспорт MD» (отчёт агента).
- «Агент». Решение (своё и по правилам), исполнитель (LLM или правила), итог сверки чисел в тексте, комментарий, обоснование, трасса шагов (шаг, инструмент, кто вызвал, статус, время, итог), полный markdown-отчёт и журнал ядра.
- «Площадка». Карта турбин и паспорт: номинал, мощность, координаты, есть ли история SCADA.
- «Факт и точность». MAE, RMSE, смещение и покрытие P10–P90 по рядам и горизонтам (`wind_agent.evaluate.evaluate`). Факт берётся из SCADA `data/raw` (есть до 31.01.2026) или из загруженного файла в том же формате (`st.file_uploader`).
- «3D-сцена». Страница `viz/index.html` (рельеф, парк, поле ветра) встроена через `components.html`. Данные `viz/data/viz_data.js` вставлены прямо в HTML, выпуск в сцене совпадает с выбранной датой. Для своей площадки над сценой выводится строка «Сцена построена для ВЭС «Нурлы»».

## Как устроено

| Файл | Назначение |
|---|---|
| `ui/app.py` | страница Streamlit: боковая панель, шапка, KPI, веерный график (Altair), вкладки |
| `ui/core.py` | мост к ядру без зависимости от Streamlit: `run_forecast(params) → ForecastResult`, агрегаты, окна рамп и штиля, лента предупреждений, факт и точность |
| `.streamlit/config.toml` | тема: нейтральный акцент вместо красного по умолчанию, светло-серая основа светлой темы; светлая или тёмная тема — по настройке системы |

- **Вызов ядра.** `run_forecast` вызывает `orchestrator.run_cycle`. Параметры `site`, `issue_hour` и `out_dir` передаются, только если `run_cycle` их принимает (проверка через `inspect.signature`). Своя площадка создаётся через `config.custom_site(lat, lon, n_turbines, rated_mw, name)`. Названия рядов не зашиты в код: все значения `turbine`, кроме `farm`, считаются турбинами.
- **Пороги.** `RAMP_THRESHOLD`, `CALM_LEVEL`, `CALM_MIN_HOURS`, `WIDE_BAND_THRESHOLD` и `REVISION_MAE_THRESHOLD` берутся из `wind_agent.agent.tools`, поэтому окна на графике и KPI считаются по тем же правилам, что у агента. Уверенность «высокая» — при ширине интервала меньше половины `WIDE_BAND_THRESHOLD`.
- **Горизонт 24 ч.** Это фильтр `lead_hours ≤ 24` на стороне UI. Агент всегда строит и проверяет 48 ч, поэтому флаги, решение и отчёт относятся к 48 ч.
- **Предыдущий выпуск.** Для «Нурлы» передаётся в анализ ревизии, как в `run_replay` и `run_live`, и рисуется пунктиром. Файлы `outputs/forecasts/<D−1>.csv` и последний `outputs/live/*Z.csv` только читаются.
- **Запись файлов.** Панель не пишет в `outputs/forecasts`, `outputs/reports` и `outputs/live`. Файлы прогона попадают в `outputs/tmp/ui/<replay|live>/<площадка>/`: каталог в `.gitignore`, его очищает `make clean`, другой путь задаётся через `WIND_AGENT_UI_OUT`. Пока `run_cycle` не принимает `out_dir`, каталог записи `tools.save_forecast` и `tools.write_report` подменяется на время прогона внутри процесса панели; код ядра не меняется.
- **Кэш.** `WeatherClient(offline=False)`, модель и факт SCADA кэшируются через `st.cache_resource`, собранный HTML 3D-сцены — через `st.cache_data`. Ключ кэша сцены — дата и время изменения файлов сцены. Прогоны идут строго по одному.
- **3D-сцена во вкладке.** Вкладки Streamlit рендерятся скрытыми, и iframe сначала получает нулевой размер. Поэтому основной модуль сцены запускается, только когда вкладка становится видимой. Сама страница `viz/` при этом не меняется: в неё добавлен лишь выбор `window.VIZ_DEFAULT_ISSUE`.

## Ограничения

- **Сеть.** Без сети доступны только данные из кэша `data/cache/openmeteo`: история «Нурлы» и тестовый период 31.01–27.02.2026. Другим датам, своим площадкам и оперативному режиму нужен Open-Meteo. При промахе ядро скачивает данные и пополняет кэш. three.js для 3D-сцены загружается с CDN jsDelivr.
- **Своя площадка.** Это перенос модели «Нурлы»: одна виртуальная турбина в ячейке сетки погоды и обобщённая кривая мощности, поэтому ошибка выше. Ревизии и факта нет. 3D-сцена показывает «Нурлы».
- **Единицы.** МВт и МВт·ч получаются пересчётом долей номинала. Паспорт «Нурлы» (2 × 2,5 МВт) берётся из `config.NURLY`.
- **LLM.** Выпуск с LLM занимает 10–40 с и расходует токены OpenAI. При сбое API агент доводит цикл по правилам.
- **Обновление ядра.** Модули ядра импортируются один раз при старте сервера. После обновления кода ядра или `models/power_model.joblib` перезапустите `make ui`.
- **Версии Streamlit.** Панель проверена на Streamlit 1.64. Аргументы, которых нет в старых версиях (спарклайны `chart_data`, ширина `width`), передаются только при наличии. Разделы `[theme.light]` и `[theme.dark]` в `.streamlit/config.toml` появились в Streamlit 1.46: на более старых версиях акцент останется красным. `components.html` в 1.6x помечен устаревшим; если его уберут, сцена встраивается через `st.iframe`.
- **Пользователи.** Панель рассчитана на одного оператора: нет авторизации и истории выпусков. Прошлые выпуски лежат в `outputs/` (CLI `wind-agent replay`).
