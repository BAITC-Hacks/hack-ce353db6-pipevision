# План решения: Agentic AI для прогноза выработки ВЭС

Дедлайн 18:00, коммит с прогрессом каждый час. Репозиторий: `BAITC-Hacks/hack-ce353db6-pipevision`.

## Идея в одном абзаце

Агент каждый день тестового периода (31.01 → 27.02.2026) «живёт в прошлом»: берёт из Open-Meteo Previous Runs API прогноз погоды, который был выпущен именно в этот день (лаг 1 и 2 суток), прогоняет его через обученную на истории модель «погода → мощность», выдаёт почасовой прогноз на 48 ч для каждой турбины и парка, сам проверяет результат (диапазоны, сравнение с вчерашним прогнозом на те же часы, климатология), пишет короткий отчёт и при появлении более свежего запуска модели погоды пересчитывает. Тот же контур в режиме `live` работает с текущим прогнозом — это готовый сервис для диспетчера.

## Ключевые решения

| Вопрос | Решение |
|---|---|
| Источник погоды | Open-Meteo: Previous Runs API (архив прогнозов с 16.02.2024, лаг day1/day2), Historical Forecast API (для 2023), Forecast API (live). Бесплатно, без ключа → жюри воспроизводит без аккаунтов |
| Модель | Градиентный бустинг на прогнозных признаках, обучение на прогнозах с реальным лагом (day1 → горизонт 1–24 ч, day2 → 25–48 ч, лаг как признак). Одна модель на две турбины + признак турбины; выход — P50 и квантили P10/P90 |
| Протокол теста | День выпуска D ∈ [31.01, 27.02]: часы D+1 из previous_day1, часы D+2 из previous_day2. Выход: `issue_date, target_time_local, target_time_utc, lead_hours, turbine, p10, p50, p90, wind_fc_100m` |
| Валидация | Holdout 01.12.2025–31.01.2026 по тому же протоколу: MAE/RMSE/nMAE против персистентности и кривой мощности. Февраль — без эталона, зато с анализом ревизий |
| Agentic-слой | Оркестратор с инструментами; LLM (OpenAI API, ключ из `.env`) объясняет результат, пишет отчёт, решает о пересчёте. Без ключа — те же шаги по правилам, отчёт по шаблону. Ключи в git не попадают |
| Воспроизводимость | `make setup && make replay` из чистого клона; кэш погоды в репо, `--offline`; Dockerfile |
