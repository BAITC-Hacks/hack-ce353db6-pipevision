# План питча для Demo Day (29.09.2026), 5 минут

Критерии Demo Day: ценность 25 · результат и качество 20 · инновационность 15 · потенциал 20 · презентация 20.

## 1. Проблема (30 с)
Диспетчер ВЭС планирует выдачу на сутки-двое вперёд, а ветер «вчерашний профиль» не повторяет: автокорреляция мощности через 24 ч — 0,10, персистентность ошибается на 37 % номинала. Ошибка прогноза = небаланс, штрафы, невозможность планировать ТО.

## 2. Решение за один экран (45 с)
WindAgent — агент, который каждый день сам: берёт архивный прогноз погоды, доступный именно в этот день (Open-Meteo Previous Runs, best_match + GFS/ICON/ECMWF), считает почасовой прогноз мощности на 48 ч с интервалом P10–P90, проверяет себя (рампы, ревизия к вчерашнему выпуску, климатология, окна штиля для ТО), при необходимости пересчитывает и пишет отчёт диспетчеру. LLM ведёт цикл через tool calling, но числа считает модель, а каждое число в тексте LLM сверяется с анализом. Без ключа — те же шаги по правилам.

## 3. Демо (90 с) — показать вживую
1. Открыть обновлённую локальную панель: три KPI, график, компактная схема расчёта. Выбрать 24/48 ч — показатели и пояснения используют один период.
2. Запустить расчёт: схема показывает реальные стадии. Включить AI-пояснения — короткий акцент подтверждает действие; подробности и чат открываются по запросу.
3. Показать отдельное исследование площадки и 3D по запросу; наветренный конус — геометрический признак, а не измерение потерь от следа.
4. Открыть архивный график февраля и прямо обозначить: эти 28 выпусков сохранены от предыдущей модели; новый артефакт не пересоздавал архив. Публичная Railway-версия обновится только после слияния PR и деплоя.

## 4. Доказательства (45 с)
- Честный бэктест дек.2025–янв.2026 по тому же протоколу: MAE 0,17223 номинала (текущий бэктест после исправления погодного контекста) против 0,210 у кривой мощности и 0,373 у персистентности (на 53,8 % ниже MAE персистентности).
- Ансамбль моделей погоды: корреляция с замером 0,78 против 0,71 у одной модели.
- Текущее покрытие интервалов: 72,81 → 75,78 % после калибровки, ниже номинальных 80 %. Калибровка сохранена в переобученной финальной модели. Надёжность ежедневного планирования пока не доказана; [результаты экспериментов](research/forecast_improvement.md).
- Воспроизводимость после получения проекта: офлайн-тесты, Makefile, Docker — проверено без API-ключей. Репозиторий требует доступа GitHub; численные расхождения Linux/macOS раскрыты в `docs/research/R4_audit.md`.

## 5. Что нашли в данных (30 с) — «инновационность»
Часовой пояс данных менялся 01.03.2024 (UTC+6 → UTC+5) — нашли кросс-корреляцией с прогнозом. Ветер бимодальный ВСВ/З; с востока замер в 1,25 раза выше прогноза (коридор), с запада 0,95 (след парка и посёлок) — модель это выучила через направление.

## 6. Потенциал (30 с)
Весь парк «Нурлы» и другие площадки Самрук-Энерго (нужна только SCADA), terrain-aware даунскейлинг (WindNinja / признаки следа), сервис для диспетчера (планировщик по запускам NWP, REST/панель, уведомления о ревизиях и окнах штиля), дообучение по факту, коммерческий NWP с ансамблевыми членами.

## Вопросы жюри, к которым готовимся
- «Почему нет метрики за февраль?» — факта в датасете нет, поэтому метрика на дек–янв по тому же протоколу; для февраля — ревизии и согласие ансамбля.
- «Что делает LLM, если числа считает модель?» — ведёт цикл, принимает решение о пересчёте/флаге, пишет объяснение; guardrail: обязательный пересчёт по правилам и проверка фактов.
- «Утечка будущего?» — только previous_day1/2 из архива запусков; фактическая погода и реанализ не используются нигде; ограничение по времени публикации запусков описано в README.
- «Почему интервал не 80 %?» — покрытие меняется по сезонам; ограниченный новый эксперимент с режимными поправками не дал стабильного выигрыша и не внедрён. Нужны данные новых сезонов и проверка по факту.
