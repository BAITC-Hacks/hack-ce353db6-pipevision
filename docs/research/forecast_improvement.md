# Проверка и исправление прогнозного конвейера · 23 сентября 2026

**Исправлена ошибка погодного контекста и переобучена модель с сохранённой калибровкой.** Соседние прогнозные часы больше не зависят от того, прошёл ли факт SCADA фильтр качества. Обучение и прогноз используют точные ±1 час внутри одного выпуска и лага. Число признаков (33), тип HGB и метод `PowerModel.calibrate` сохранены. Модель и исторический бэктест связаны проверяемым манифестом для панели.

**Улучшение общей точности не подтверждено:** на прежнем итоговом периоде MAE выросла с 0,170640 до 0,172231 (+0,93%); MAE на фактических рампах уменьшилась на 0,56%. Изменение исправляет достоверность конвейера; сохранять ошибку ради более красивой метрики было бы неверно. Исследованные улучшения центрального прогноза/интервалов не внедрены. Материалы R1/R2/R3/R4 сохранены как исторические исследования.

## Внедрённое исправление соседних часов

Раньше `training_frame` сначала исключал часы с отсутствующим/недостаточным/ограниченным фактом, затем `make_features` делал `groupby(turbine, lead).shift(±1)`. Следующая сохранившаяся строка могла быть через несколько часов. Кроме того, исторический сдвиг пересекал границы суточных выпусков, тогда как прогнозный вход ограничен горизонтом выпуска. В 64 206 строках обучения обнаружено **392 перехода к предыдущей строке через разрыв**; вместе с границами выпусков изменены 3 038 предыдущих и 3 033 следующих значения погодного контекста.

Теперь `data.weather_neighbors` ищет точный час по ключу «турбина, выпуск, лаг, время». Отсутствующий сосед и край горизонта дают текущую скорость. В обучении это вычисляется **на полном NWP-ряде до соединения и фильтрации SCADA**. В прогнозе используется явный `issue_time_utc`; поэтому нестандартный выпуск в 12:00 корректно проходит через местную полночь внутри своего lead. Для исторической обучающей выборки границы соответствуют установленному выпуску в 23:00. Порядок строк не влияет на результат, турбины и лаги не смешиваются. Поддерживаются timestamp-разрешения ns и us. Отдельно исключён повторный местный 23:00 при переходе Казахстана UTC+6→UTC+5: сосед должен отличаться на час также по местной временной шкале, как в сетке serving. Для этой границы добавлен regression-тест.

Ранние окна **финального исправления, включая переход часового пояса**, дали следующие относительные изменения:

| Окно | MAE | RMSE | MAE на рампах |
|---|---:|---:|---:|
| 12.2024–01.2025 | +1,39% | +1,68% | +0,22% |
| 08–09.2025 | +0,56% | +0,11% | +1,33% |
| 10–11.2025 | +0,92% | +1,08% | +0,50% |

Промежуточный вариант с двумя соседними часами среднего ансамбля проверялся **до последнего уточнения перехода часового пояса**: MAE по окнам +2,79% / −1,92% / −0,66%, осенняя MAE рамп +4,75%. Его сохранённые результаты описывают тот промежуточный кандидат, а не финальную production-матрицу; эти числа не использованы как подтверждение финального исправления.

Дополнительные признаки ансамбля отклонены из-за ухудшения рамп осенью. Ни один вариант не прошёл исходный gate «выигрыша точности». Минимальное исправление внедрено **по критерию корректности входных данных**, а не выбрано по итоговому тесту. Прежний тест уже был открыт; последующее сравнение является exploratory и не новым слепым подтверждением.

## Протокол и границы вывода

В следующих экспериментах база — исходная модель после R1, до исправления соседей: 33 признака, HGB с `squared_error` для центрального прогноза, P10/P90 и существующая `PowerModel.calibrate`. Данные и фильтрация SCADA неизменны. Одна строка — турбина × целевой час × лаг; 5 884 строки итогового теста не являются 5 884 независимыми наблюдениями.

Кандидаты P50 выбирались на трёх временных окнах: декабрь 2024–январь 2025, август–сентябрь 2025, октябрь–ноябрь 2025. Обучение каждого окна использует только более ранние строки. Сначала проверены `squared_error`, `absolute_error` и их смесь 50/50. Медиана и 50/50 не прошли ограничение по рампам. До сравнения на итоговом тесте добавлены ещё два кандидата: смесь 75/25 и `squared_error` с 15 листьями. Остальные параметры не подбирались.

Критерий отбора: минимальное среднее отношение MAE к базе; ни одно окно не хуже базы более чем на 1%; средние отношения RMSE и MAE на фактических рампах не выше 1,02. Рампа — изменение факта не менее 0,3 номинала за час. Разрывы ряда исключены; изменения прогнозов разных выпусков не считаются предсказанной рампой. Это диагностический порог R3, а не порог предупреждения панели.

Итоговое сравнение выбранного кандидата выполнено один раз на декабре 2025–январе 2026, после фиксации выбора. **Этот период уже изучался проектом в R1/R3; его нельзя считать совершенно новым независимым тестом.** В данном эксперименте он не использован для выбора веса/параметров. Дополнительный эксперимент с интервалами предложен уже после просмотра итогового результата и явно помечен exploratory; на итоговом тесте его не оценивали.

Среда: macOS, Python 3.11.15, scikit-learn 1.9.1, `OMP_NUM_THREADS=2`, `OPENBLAS_NUM_THREADS=2`. Воспроизведённая база совпала с сохранённым бэктестом R1: MAE **0,1706399077**. Межплатформенные численные различия остаются возможны.

## Проверка калибровки по режимам ветра

Один ограниченный кандидат: та же нормированная CQR, отдельно по лагу и прогнозному ветру **<3 / 3–9 / ≥9 м/с**, не менее 200 строк в группе, иначе fallback на действующую поправку по лагу. Два калибровочных месяца непосредственно предшествуют каждому раннему тесту; модель для оценки невязок не видит эти месяцы. После калибровки применяется действующий механизм переноса поправок на модель, переобученную по всей предшествующей истории. Центральный прогноз неизменен.

Проверялось не только покрытие: interval score для 80%-интервала равен ширине плюс десятикратный выход факта за нижнюю/верхнюю границу. Он штрафует и чрезмерно широкие интервалы, и промахи. Gate: средний относительный score ≤0,99; ни одно окно score >1,02 или ширина >1,10; средняя относительная ошибка покрытия групп уменьшается; общее покрытие ближе к 80% минимум в двух окнах.

| Тестовое окно | Покрытие базы → кандидата | Interval score базы → кандидата |
|---|---|---|
| 12.2024–01.2025 | 89,62% → 89,76% | 0,63191 → 0,63397 |
| 08–09.2025 | 80,59% → 81,60% | 0,68490 → 0,69101 |
| 10–11.2025 | 84,30% → 84,21% | 0,60839 → 0,60736 |

**Кандидат отклонён:** средний относительный score хуже на 0,35%, ширина больше на 1,19%, ошибка покрытия по группам выше на 9,98%; только одно окно приблизилось к 80%. [Протокол, поправки, размеры групп и результаты](data/forecast_improvement/interval_validation.json).

Покрытие заметно меняется между временными окнами. Перенос поправок на переобученную модель и временная зависимость данных не дают строгой гарантии split-conformal на будущих часах. Нельзя обещать оператору «надёжные 80%» только из названий P10/P90. Следующий содержательный шаг — накопление строго доступных на момент выпуска NWP-снимков, непрерывная проверка по сезонам и отдельный операционный тест на рампах/ограничениях. Подстройка небольшой поправки не заменила такую проверку.

## Воспроизведение

Исследовательские команды из корня checkout, после установки зависимостей проекта; работают офлайн и не меняют production-артефакт:

```bash
export OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MPLCONFIGDIR=/tmp/wind-mpl PYTHONPATH=src
python scripts/research_forecast_improvement.py
python scripts/research_forecast_improvement.py --holdout
python scripts/research_forecast_intervals.py
python scripts/research_weather_neighbors.py
python scripts/research_weather_neighbors.py --holdout
python -m pytest -q tests/test_forecast_research.py
```

Отрицательные промежуточные проверки ансамбля и early stopping сохранены в JSON. Флаги `--ensemble-context` и `--all-training-rows` исследовательского скрипта позволяют повторить их **на текущей матрице**; это уже другой вариант после уточнения часового пояса, поэтому исходные промежуточные цифры могут отличаться.

Первый запуск сохраняет выбор в `validation.json`; `--holdout` читает этот выбор, не оптимизирует его по итоговому тесту. Повторное воспроизведение того же замороженного сравнения не является новым независимым подтверждением. Наблюдённое время вычислений: ранний отбор ~11 с, итоговое сравнение ~17 с, интервалы ~34 с; не SLA.

Четыре теста проверяют сохранение калибровки при сериализации кандидата, корректную смесь и clipping, режимную поправку и fallback при малой группе, proper interval score и исключение разрывов/смены выпуска при оценке рамп. Исследовательские кандидаты не меняют `PowerModel.calibrate`. Production-изменения описаны отдельно выше.

Обновление production-артефакта после исправления (пишет `models/` и `outputs/backtest_*`; исторические R3 не пересоздаются):

```bash
python -m wind_agent backtest --offline
python -m wind_agent train --offline
python scripts/write_validation_manifest.py
python -m pytest -q tests/test_features.py tests/test_data.py tests/test_model.py tests/test_calibration.py tests/test_agent.py tests/test_forecast_research.py
```

Дополнительные проверки проверяют независимость NWP-контекста от трёх причин отбрасывания факта (пропуск, мало замеров, ограничение), точные соседние часы при разрывах/перестановке строк, границы выпуска/лага и паритет обучения с прогнозом для сохранившихся целевых часов.

После финального уточнения часового пояса повторены backtest, train и генерация манифеста. Проверены все SHA256, точное совпадение прогнозов CLI с независимым итоговым расчётом, четыре офлайн-прогноза (T1/T2 × выпуск 12:00/23:00) и наличие сохранённых конформных поправок.
