## 2. Что мешало начать дословно

В голом `python:3.11-slim` первые команды README дают:

```text
git clone …  → bash: git: command not found  (exit 127)
uv venv …    → bash: uv: command not found   (exit 127)
```

Для проверки установлены системные предпосылки:

```bash
apt-get update
apt-get install -y --no-install-recommends git make ca-certificates
python -m pip install uv   # только в uv-контейнере
```

После этого анонимный клон из README в обоих контейнерах также не проходит:

```text
fatal: could not read Username for 'https://github.com': No such device or address
# exit 128; около 0,44 с
```

`gh repo view --json isPrivate,visibility` из авторизованной среды подтвердил `isPrivate: true`, `visibility: PRIVATE`. Это ограничение доступа, а не ошибка Git или Python. Для продолжения аудита передан Git bundle указанного коммита с авторизованной машины; в контейнере создан свежий клон его ветки `research/R4`. Учётные данные GitHub не переносились. Тем самым проверены установка и вычисления из чистых исходников, **но анонимное получение приватного репозитория не объявляется успешным**.

В README добавлены необходимые инструменты, требование доступа GitHub или предоставленного командой архива и разделение доступа к репозиторию от API-ключей приложения. Видимость репозитория этим PR не меняется.

## 6. Предупреждения в логах

- При `wind-agent replay` и исходном полуденном примере без `--no-llm`: предупреждение об отсутствии `OPENAI_API_KEY`, затем штатный fallback на правила. Явный `--no-llm` устраняет неоднозначность и это предупреждение.
- Docker-сборка / установка uv системным pip: стандартное `Running pip as the 'root' user…`. В данном аудите установка идёт внутри одноразового контейнера; установка приложения в venv проходит без этой причины предупреждения.
- Системная установка пакетов в slim выдаёт сообщения `debconf` о недоступном интерактивном frontend / `apt-utils`; установка завершается успешно. Это подготовка ОС, не ошибка приложения.
- Streamlit AppTest: `Thread 'MainThread': missing ScriptRunContext! ... bare mode` — предупреждение тестового запуска; UI не показал исключений.
- Streamlit при построении 3D-вкладки: `Please replace st.components.v1.html with st.iframe.` и `st.components.v1.html will be removed after 2026-06-01.` Несмотря на указанный срок, установленный Streamlit 1.64.0 пока выполняет этот путь. Миграция API остаётся отдельной задачей кода, а не скрывается исправлением README.

HTTP-проверка не подменяет проверку содержимого и прав доступа: HTTP 200 у Google Drive подтверждает страницу просмотра, а не возможность скачать вложение без авторизации. ## 8. Границы результата

Проверен Linux arm64 в контейнере, а не отдельная x86-машина, Windows/WSL или повторное обучение на macOS. Поставленные macOS-артефакты использованы как база сравнения. Внешний доступ к GitHub проверен без аутентификации и оказался закрыт. Платные LLM-вызовы, оперативная погода `live`, новые площадки, повторная загрузка DEM/OSM и качество 3D-рендера в реальном браузере не проверялись; они не входят в доказательство офлайн-воспроизводимости. UI проверен установкой, HTTP health и AppTest, а не визуальным приёмочным тестом.

PR R4 содержит только README, документы сдачи/питча, инструкции UI/viz и этот отчёт. Ядро, тесты, Makefile, Dockerfile, lock-файл, модель, её калибровка, данные и поставленные `outputs/` не меняются. Доступность приватного репозитория, межплатформенная численная идентичность и будущая миграция Streamlit остаются раскрытыми ограничениями.
