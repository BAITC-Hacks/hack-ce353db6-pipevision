## Задача (по ТЗ)

Нужна Agentic AI-система для **почасового** прогноза выработки ВЭС на горизонте **24–48 ч**.

- История: с марта 2023 по 31.01.2026 включительно. Тестовый период: **01.02.2026–28.02.2026**.
- Что должно делать решение:
  1. Строить модель прогноза почасовой выработки на исторических данных.
  2. Самостоятельно брать по координатам ВЭС погодные прогнозы из открытых источников, **доступные на момент прогноза**.
  3. Выдавать прогноз на следующие 24–48 ч с почасовой детализацией.
  4. Работать как агент, который сам проходит полный цикл: получить погоду → подготовить данные → запустить модель → сформировать почасовой прогноз → проанализировать результат → пересчитать при обновлении входных данных.
- Прогноз воспроизводится «как в прошлом»: прогноз на 31.01 на 24–48 ч вперёд, затем на 01.02, и так далее по дням до конца теста.
- Использовать можно только **архивные прогнозы**, доступные на тот момент. Фактическую погоду, ставшую известной позже, брать нельзя.
- Источники погоды, ML-модели, методы и архитектура агента — на выбор участников.
- Карточка на платформе: «Агент сам берёт архивный прогноз погоды по координатам турбин и обновляет расчёт на каждый день тестового февраля 2026 года».

## Правила и сроки, важные для работы

- **Сегодня, 23.09.2026:** соревновательная часть **13:00–18:00** по Астане (в метаданных: endDate `2026-09-23T13:00:00Z`). Оценивается то, что лежит в репозитории на **18:00**. Более поздние изменения не учитываются (п. 5.4.13–5.4.14).
- Вся разработка ведётся **только в GitHub-репозитории команды**, который создаёт платформа edu.astanahub.com. Нужна подтверждаемая история коммитов (п. 5.4.9, 5.4.11).
- **Каждый час** нужен промежуточный результат (коммиты, функционал, схема и т.п.). Если его нет — дисквалификация (п. 5.4.8, 5.9.2).
- README обязателен: описание, архитектура, технологии, установка, запуск, зависимости, переменные окружения, как проверить основной сценарий (п. 5.4.15). Если проект не запускается по README, команда выбывает из отбора, исправления не принимаются (п. 5.4.16).
- Проверка должна быть возможна **без личных аккаунтов и подписок**. Для внешних API нужно дать демо-доступ или другой способ проверки (п. 5.6.6). **API-ключи не публиковать в GitHub** (инструкция).
- Использованный сторонний код, модели и датасеты нужно раскрыть. Open-source разрешён (п. 5.4.4). Любые AI-инструменты разрешены, Codex не обязателен (п. 5.4.12).
- Заготовки и библиотеки допустимы, но основная функциональность должна быть сделана во время соревнования (п. 5.4.4.2, 5.4.5).
- Включён **AI-судья** (`aiScoringEnabled: true`), он делает предварительную оценку (п. 4.2–4.4).
- Этапы после сегодняшнего дня: 24–28.09 — проверка экспертами, 29.09 — Demo Day, 01.10 — награждение. Всего 10 призовых мест, единый зачёт по всем задачам.
- Сдача: страница треков → кейс → «Сдать решение» → название и описание. Обновлять можно до дедлайна.
- Площадка: из зоны хакатона можно выходить суммарно не больше чем на 60 мин. В последний час (17:00–18:00) выходить нельзя. Каждый участник должен внести личный вклад.

## Проверенный источник архивных прогнозов погоды

Open-Meteo без ключа отдаёт данные по координатам турбины 1 за 01.02.2026 (проверено запросом):
- **Previous Runs API** — `https://previous-runs-api.open-meteo.com/v1/forecast`: переменные `*_previous_day1`, `*_previous_day2` и т.д., то есть прогноз, выпущенный за N дней до даты. Ответ содержит wind_speed_10m/80m и temperature_2m, у значений previous_day1/day2 они отличаются от day0.
- **Historical Forecast API** — `https://historical-forecast-api.open-meteo.com/v1/forecast`: прогнозы, склеенные из свежих запусков моделей. Ответ содержит wind_speed_10m/100m, wind_direction_100m, temperature_2m.
- Open-Meteo привязал точку к узлу сетки 43.620, 78.479 (высота 555 м). Часовой пояс Asia/Almaty = UTC+5.
